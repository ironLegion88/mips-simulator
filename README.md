# Interactive MIPS Assembly Converter and Simulator

**Course:** Computer Organization and Systems
**Project:** Web-Based MIPS ISA Educational Tool

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

## Overview

This project is a web-based educational tool designed to enhance understanding of the MIPS (Microprocessor without Interlocked Pipeline Stages) instruction set architecture (ISA). It provides an interactive environment for students and enthusiasts to:

1.  **Convert** MIPS assembly code to machine code (binary/hex/decimal) and vice-versa (disassemble).
2.  **Simulate** the execution of MIPS programs step-by-step or continuously.
3.  **Visualize** the internal state of a MIPS processor, including registers and memory, as the program executes.
4.  **Observe** the interaction between software instructions and hardware components in a simplified model.

The goal is to bridge the gap between theoretical MIPS concepts learned in computer organization courses and the practical execution flow within a processor, making abstract concepts more tangible and easier to grasp.

## Features

This simulator implements a significant subset of the MIPS I ISA and provides several helpful features for learning:

**1. MIPS Conversion Tools:**
    *   **Assembler (Assembly -> Machine Code):**
        *   Supports a wide range of standard MIPS instructions (R-type, I-type, J-type) including arithmetic, logical, memory access, branches, and jumps.
        *   Implements a **two-pass** approach to handle forward label references correctly.
        *   Handles common **assembler directives** (`.data`, `.text`, `.word`, `.byte`, `.half`, `.asciiz`, `.ascii`, `.space`, `.align`, `.globl`, `.extern`).
        *   Automatically detects and expands common **pseudo-instructions** (`li`, `la`, `move`, `nop`, `blt`, `bgt`, `ble`, `bge`, `clear`, etc.) into core MIPS instructions.
        *   Outputs machine code in **Binary**, **Hexadecimal**, and **Unsigned Decimal** formats.
        *   Generates a `.data` segment byte representation.
    *   **Disassembler (Machine Code -> Assembly):**
        *   Converts 32-bit hexadecimal machine code back into human-readable MIPS assembly instructions.
        *   Identifies instruction types (R/I/J) based on opcode and funct codes.
        *   Resolves register numbers to standard names (e.g., `$t0`, `$sp`).
        *   Calculates target addresses for branches and jumps relative to a base PC (0x00400000).
    *   **Syntax Highlighting & Validation:**
        *   Provides syntax highlighting in the editor for MIPS assembly (opcodes, registers, labels, directives, numbers, strings, comments).
        *   Performs basic syntax validation during assembly, reporting errors like invalid register names, incorrect operand counts, immediate values out of range, undefined labels, and directive misuse.

**2. Execution Simulation & Visualization:**
    *   **Step-by-Step Debugger:**
        *   Executes MIPS code one instruction at a time (`Step` button).
        *   Supports continuous execution with adjustable delay (`Run` button).
        *   Allows pausing (`Pause`) and resetting (`Reset Sim`) the simulation state.
    *   **Register Visualization:**
        *   Real-time display of all 32 General Purpose Registers (GPRs), PC, HI, and LO registers.
        *   Values shown in Hexadecimal and Signed Decimal formats.
        *   **Highlights registers** whose values change after a simulation step.
    *   **Memory Visualization:**
        *   Displays relevant segments of memory (initial `.data` section, stack area around `$sp`).
        *   Shows memory contents as words (Address -> Hex/Decimal Value).
        *   **Highlights memory words** whose values change after a simulation step.
        *   Indicates the current Stack Pointer (`$sp`) position within the memory view.
    *   **Stack Simulation Visualization:**
        *   Implicitly simulated through standard instructions (`addiu $sp, $sp, +/-imm`, `sw`, `lw`).
        *   Memory view automatically tracks and displays the region around `$sp`, allowing observation of stack growth/shrinkage.
    *   **Active Instruction Highlighting:**
        *   Highlights the line in the assembly code editor corresponding to the current Program Counter (PC) value during stepping or running.
    *   **I/O Console:**
        *   Displays output generated by `print_int`, `print_string`, `print_char` syscalls.
        *   Accumulates output across multiple simulation steps.
        *   Provides an input field when `read_int` or `read_string` syscalls are encountered, pausing execution until input is submitted.
        *   Echoes user input back to the console upon successful read.
    *   **Hardware Unit Visualization (Planned/Partial):**
        *   *Future:* Graphical blocks representing Register File, ALU, Memory, etc.
        *   *Future:* Highlighting blocks used by the currently executing instruction.

**3. Educational Enhancements:**
    *   **Error Reporting:**
        *   Provides clear assembly-time error messages with line numbers.
        *   Reports runtime errors detected during simulation (e.g., unaligned memory access, division by zero, invalid instruction fetch, arithmetic overflow, unimplemented syscalls/instructions).
        *   Distinguishes program termination reasons (syscall exit vs. running off end).
    *   **Pre-Loaded Code Examples (Planned):**
        *   *Future:* Include examples for common algorithms (factorial, array sum, string copy) and concepts (function calls).
    *   **Export Options (Planned):**
        *   *Future:* Allow downloading the current assembly code (`.s`) or the assembled machine code (`.hex` or `.bin`).

## Architecture Overview

The application follows a standard **Client-Server architecture**:

1.  **Frontend (Client):** A React single-page application (built with Next.js) running in the user's browser.
    *   Provides the user interface (code editor, buttons, visualization panels).
    *   Uses the **Monaco Editor** component for a rich code editing experience with syntax highlighting.
    *   Communicates with the backend via **RESTful API calls** (using `axios`) to request assembly, disassembly, simulation load/step/run operations.
    *   Dynamically updates the UI based on the state received from the backend (registers, memory, PC, status, output).
    *   Manages the animated "Run" feature using `setInterval` to call the backend's step endpoint repeatedly.
2.  **Backend (Server):** A Python Flask application serving the API endpoints.
    *   Receives requests from the frontend.
    *   Uses dedicated Python classes for core logic:
        *   `MipsAssembler`: Parses assembly code, resolves labels, expands pseudo-instructions, handles directives, and generates machine code and data segments.
        *   `MipsDisassembler`: Decodes machine code back into assembly text.
        *   `MipsSimulator`: Maintains the MIPS machine state (registers, memory, PC), fetches/decodes/executes instructions, handles memory access, and simulates syscalls.
    *   Returns results (machine code, assembly text, simulator state, errors) to the frontend as JSON objects.

**Interaction Flow (Example: Assemble & Step):**

1.  User types MIPS code in the Monaco Editor (Frontend).
2.  User clicks "Assemble".
3.  Frontend sends the assembly code text to the `/api/assemble` endpoint (Backend).
4.  Backend's `MipsAssembler` processes the code (two passes).
5.  Backend returns JSON containing machine code, data segment, address map, and any errors.
6.  Frontend displays the machine code/errors and stores the result.
7.  User clicks "Load Simulation".
8.  Frontend sends the machine code and data segment to `/api/simulate/load` (Backend).
9.  Backend's `MipsSimulator` initializes its state (registers, PC, memory).
10. Backend returns the initial simulator state (PC, registers, memory view).
11. Frontend updates the Register, Memory, and PC display panels.
12. User clicks "Step".
13. Frontend sends a request to `/api/simulate/step` (Backend).
14. Backend's `MipsSimulator` executes one instruction, updating its internal state.
15. Backend returns the *new* simulator state.
16. Frontend updates displays, highlighting changes and the active instruction line.

## Getting Started

### Prerequisites

*   **Git:** To clone the repository.
*   **Python:** Version 3.8 or higher recommended. ([Download Python](https://www.python.org/downloads/))
*   **pip:** Python package installer (usually comes with Python).
*   **Node.js:** LTS version recommended (includes `npm`). ([Download Node.js](https://nodejs.org/en/download/))
*   **(Optional) `yarn`:** Alternative Node.js package manager (`npm install -g yarn`).

### Setup

1.  **Clone the Repository:**
    ```bash
    git clone <repository-url>
    cd mips-simulator
    ```

2.  **Backend Setup (Python/Flask):**
    ```bash
    # Navigate to the backend directory
    cd backend

    # Create a Python virtual environment
    python -m venv venv

    # Activate the virtual environment
    # Windows (Command Prompt/PowerShell):
    .\venv\Scripts\activate
    # Linux/macOS/Git Bash:
    # source venv/bin/activate

    # Install required Python packages
    pip install -r requirements.txt
    # (If requirements.txt doesn't exist yet, run: pip install Flask Flask-Cors pytest)

    # Create an empty __init__.py file if it doesn't exist
    touch __init__.py
    cd ..
    ```

3.  **Frontend Setup (Node.js/Next.js):**
    ```bash
    # Navigate to the frontend directory
    cd frontend

    # Install Node.js dependencies
    npm install
    # or: yarn install
    cd ..
    ```

### Configuration

*   **(Optional) Backend Port:** The backend Flask server defaults to port `5001`. If this conflicts, you can change the port number in the `app.run(...)` call at the bottom of `backend/app.py`.
*   **(Optional) Frontend Port:** The frontend Next.js server defaults to port `3000`. You can run it on a different port using `npm run dev -- -p <new_port>`.
*   **CORS:** The backend `app.py` currently allows requests from `http://localhost:3000`. If your frontend runs on a different origin during development or in production, update the `CORS(app, ...)` configuration in `backend/app.py`.

## Running the Application

You need to run both the backend and frontend servers simultaneously.

1.  **Start the Backend Server:**
    *   Open a terminal in the **project root directory** (`mips-simulator`).
    *   Activate the Python virtual environment:
        ```bash
        # Windows
        .\backend\venv\Scripts\activate
        # Linux/macOS
        # source backend/venv/bin/activate
        ```
    *   Set the `FLASK_APP` environment variable:
        ```bash
        # Windows (Command Prompt)
        set FLASK_APP=backend.app
        # Windows (PowerShell)
        $env:FLASK_APP = "backend.app"
        # Linux/macOS
        export FLASK_APP=backend.app
        ```
    *   Run the Flask development server:
        ```bash
        flask run --port 5001
        ```
    *   Keep this terminal running.

2.  **Start the Frontend Server:**
    *   Open a **separate** terminal in the **project root directory** (`mips-simulator`).
    *   Navigate to the frontend directory:
        ```bash
        cd frontend
        ```
    *   Run the Next.js development server:
        ```bash
        npm run dev
        ```
    *   Keep this terminal running.

3.  **Access the Application:**
    *   Open your web browser and navigate to `http://localhost:3000` (or the port specified by `npm run dev`).

## Usage Guide

1.  **Code Editor:** Enter your MIPS assembly code in the left-hand editor pane. Syntax highlighting is provided.
2.  **Assemble:** Click the "Assemble" button. The corresponding machine code will appear in the "Machine Code Output" panel below the editor. You can switch between Hex, Binary, and Decimal formats using the radio buttons. Any assembly errors will be displayed in the red error box at the top.
3.  **Disassemble:** Enter 32-bit hexadecimal machine code (one instruction per line, `0x` prefix optional) into the "Machine Code Input" text area on the right. Click "Disassemble" to see the corresponding assembly code in the "Assembly Output" panel.
4.  **Load Simulation:** After successful assembly, click the "Load Simulation" button. This initializes the simulator with your code and data. The "Registers" and "Memory View" panels will populate with initial values (PC at text start, $sp at stack top, registers zeroed, data segment loaded).
5.  **Step:** Click the "Step" button to execute the single instruction indicated by the highlighted line in the editor and the current PC value. Observe changes in the Registers and Memory panels (changed values will be highlighted briefly). Output from `print_*` syscalls will appear in the "I/O Console".
6.  **Run:** Click the "Run" button to execute instructions sequentially with a short delay. The UI will update dynamically. Execution continues until the program finishes, requires input, hits an error, or the "Pause" button is clicked.
7.  **Pause:** Click the "Pause" button while the simulation is running (via the "Run" button) to halt execution.
8.  **Input:** If the program executes a `read_int` or `read_string` syscall, execution will pause, the status will change to `input_wait`, and an input box will appear below the I/O Console. Type the required input and click "Submit" or press Enter to continue execution. The input will be echoed to the console.
9.  **Reset Sim:** Click the "Reset Sim" button to clear the simulator state (registers, memory, PC) back to its default initial state. You will need to click "Load Simulation" again to reload the last assembled code.
10. **Memory View:** Shows words from the start of the `.data` segment and the area around the current Stack Pointer (`$sp`). The address pointed to by `$sp` is marked.
11. **I/O Console:** Displays all output generated by the program's `print_*` syscalls cumulatively, including echoed user input.
